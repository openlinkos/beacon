# 密钥的设计

Beacon 为什么替 Agent 保管它们干活用的凭据，以及这一部分的形状：从三个已经解决过的问题各借了什么、什么是配置、哪四件事永远不是。本页讲为什么；[管理 Agent 的密钥](../guide/secrets.md)讲怎么用，[设置](../reference/settings.md)列出每个配置项和默认值，[威胁模型](../self-hosting/security.md)在安全模型页。

一个做运维的 Agent 迟早会拿到它所维护服务的凭据：API 令牌、数据库密码、DNS 密钥。把它们复制进 Agent 的上下文，就是它们最终出现在转写记录、提示词或代码仓库里的路。Beacon 改为替它保管：Agent 申请一次，生成一份授权——由规则、审核 Agent 或人批准——此后在授权范围内取多少次都行，每一次都有记录。

## 三个问题，三个成熟答案 {#three-problems-three-mature-answers}

设计不发明新东西；它组合三个已被解决的问题各自的经验，再添上自己的一点。

| 问题 | 成熟答案 | Beacon 取什么 |
| --- | --- | --- |
| 把凭据放在能交给无人值守者手里的保管处 | 服务端托管的密钥库：Vault、Infisical、1Password Connect——服务器持有能解密的密钥 | 数据模型：密钥层级、每个库一把密钥、供搜索和策略用的明文概要、加密的值。服务器必须能解密，否则凌晨三点没人能把值交给 Agent；「服务器什么都不知道」是另一类产品 |
| 给一个「申请人本身是软件」的即时特权访问 | GCP Privileged Access Manager、Entra PIM、Teleport Access Requests | 资格（谁可以申请什么），写明条目、动作、次数、期限和原因的授权，不能自批，审批门槛，必填原因 |
| 自托管控制面的状态与备份 | Teleport、Gitea、Grafana：默认 SQLite，需要时换更大的数据库；age 加密的备份；带签名的审计摘要 | 存储层、备份设计和审计链（见[架构](architecture.md)、[备份与恢复](../self-hosting/backup.md)） |

Beacon 自己添的东西少而有意：申请人和审核人都可以是 Agent。Agent 能申请什么仍由人定；凌晨三点某个申请是否合理，可以由规则、另一个 Agent 或人来判断——由谁判断，是配置。

## 一次授权，多次使用，每次有记录 {#one-grant-many-uses-every-use-on-record}

核心是[目标 2](goals.md#product-goals-three-pillars)：一次授权、多次使用、全程可追溯。

- 一份**授权**写明条目、字段、动作、次数和期限——次数和期限都可以不限——以及批准它的理由。Agent 可以按批准人允许的期限长期持有授权，也可以续期。
- 授权范围内的每次**取用**不打扰任何人：没有卡片，没有等待。但每次都带原因，并且在值返回之前，先以 Agent、它代表的人、所用授权和上下文（告警、会话）为名记进记录。
- Agent 读到值之后拿它做什么，是它自己的行为；授权框住它能取多少，并写下谁取的、为什么。嫌这不够的地方，可以把条目限制为[不见值的用法](../guide/secrets.md#using-a-secret-without-seeing-it)。

## 两个轴：级别与资格 {#two-axes-the-level-and-the-entitlement}

两个分开问的问题，合起来回答：

- **条目的级别**——`auto`、`review`、`person` 或 `never`——说明申请它要什么：有资格即可、走审核、只能人批，或者任何 Agent 都拿不到。级别放在库、标签和条目上，取最严的。
- **Agent 的资格**——按库、标签或条目，动作分 `describe`、`read` 和 `use`——说明它连能申请什么。没有资格的 Agent 根本看不到那个条目；`deny` 资格优先于一切；Agent 能拿到的不超过其所有者的权限。

一次申请需要的审批取两者中更严的。处处默认拒绝；一次申请也可以按级别拆开，`auto` 的部分立即可用，其余各自等待。

## 一切都是配置 {#everything-is-a-setting}

默认值开箱即用，而且每一个都是数据库里的配置项，带版本、修改人、原因，可以回滚：申请可以等多久、审核人不答复怎么办、一个级别要几个批准、限流、什么算异常、保留期、导入规则。系统定下限，库、标签、资格、申请可以再收紧。凌晨三点什么行为是对的，不该由软件去猜；它被写下来，改动留有记录。

## 加密与签名 {#encryption-and-signatures}

根密钥包裹每个库一把的库密钥；条目的详情——全部字段值、用户名、笔记、一次性验证码种子、附件——用库密钥加密，并绑定条目、版本和库。概要——标题、类别、标签、网址、字段名——保持可读，因为策略和搜索要用；只拿到数据库的人知道有哪些密钥，不知道它们的内容。

根密钥默认来自一个文件；可以拆成口令加文件，或交给 KMS 包裹，让整块磁盘不足以打开密钥库（见[安全模型](../self-hosting/security.md#unsealing-the-root-key)）。

策略行——资格、授权、配置——带签名。签名校验不过的行被当作不存在，并告警：直接改数据库的人放大不了任何权限。

## 审计链 {#the-audit-chain}

每一件事——条目的新建、修改、归档、导入；申请的裁决；授权的生成、取用、续期、吊销；密钥的轮换、封存、启封；备份与恢复——都是一条记录：谁、代表谁、做了什么、为什么、从哪里来。记录组成哈希链，签名检查点按周期写进数据库和每份备份。记录按保留期清理，检查点留下，剩下的链仍可校验。取用先写记录，再返回值；记录写不进去，值就不返回。

## 四条不变量 {#the-four-invariants}

四件事不是配置，因为其余一切都站在它们上面：

1. 取用记录先提交，值后返回。没有它就没有可追溯。
2. 申请人不得审批自己的申请。没有它就没有审批。
3. 签名校验不过的策略行视为不存在，并告警。没有它，改一行数据库就能绕过一切。
4. `never` 级条目不交给任何 Agent。这正是这个级别的定义；想让 Agent 用，改级别。

## 借来的东西 {#what-it-borrows}

都是公开的设计，指名道姓：从 1Password 学两段密钥派生、每库一把密钥、概要与详情的拆分，以及 `beacon://` 所对照的 `op://` 引用语法；从 GCP PAM 和 Teleport 学资格、必填理由、审批门槛和拒绝自批；从 Vault 学默认拒绝、`deny` 优先和按次数的令牌；从 CloudTrail 学对日志链周期性签名摘要；从 restic 学祖父—父—子保留；从 age 学加密给公钥，让写备份的一方读不了自己写的备份。

## 它有意不做的事 {#what-it-deliberately-is-not}

服务器能解密，所以中心被攻破等于密钥库被攻破——不比它已经承担的 SSH 证书机构更轻也不更重（见[威胁模型](../self-hosting/security.md#the-threat-model)）。概要是明文。读到值的 Agent 可以外泄它；授权框住它拿到的范围，并把它的名字写在每一次取用上，更严的路是不见值的用法。转写记录里的打码防的是无意泄露，不是存心。Beacon 也不调用任何模型：审核 Agent 在外部，像值班 Agent 一样被唤醒，它能批什么由配置约束。
