# 目标

Beacon 为什么而做、不做什么、目标互相冲突时怎么取舍。每一处改动都应该服务其中某个目标。做计划时写明是哪一个。

## 北极星 {#north-star}

Beacon 是 AI 时代基础设施中的一环。做它的人做这一类基础设施，是为了拿掉 AI 和 Agent 干活时碍事的东西。其他环节（比如跨会话留存的记忆）是别的项目。Beacon 只守自己这一环。

它这一环，是 Agent 干活要经过的基础设施，并且和管理 Agent 的人共用：

- **Agent** 取用授权给它的凭据，登上机器，看清自己运行的和自己开发的东西是否正常。
- **人**在同一个地方做同样的事，并决定每个 Agent 能用什么。
- **双方**做的每一件事都有记录，都能追溯。

从三个角度衡量：

- **覆盖**：Agent 用到的凭据、机器和服务，有多少经过 Beacon。目标：全部，没有一份凭据经别的途径交到 Agent 手里。
- **替代**：在 Beacon 运行的地方，人用它代替各管一件事的工具：密码管理器、跳板机、可用性监控。目标：这些工具都退役。
- **闭环**：严重告警里，有多少由 Agent 从被唤醒一直做到验证恢复，中间没有人插手。目标：多数。这是几项能力合在一起才做得到的闭环。

三条底线不拿来换上面任何一项：没有一步不留记录，不泄露凭据，不丢告警。一项改动既不推进任何一项衡量，也不守住哪条底线，就先放一放。

## 一句话 {#in-one-sentence}

Beacon 是 AI Agent 和管理它们的人共用的自托管基础设施：团队密码管理器、Agent 的可信访问、SSH 跳板机，以及带告警和视图的监控，既管你的机器，也管你的 Agent 开发的服务；一切都可追溯。

两条检验标准：

- **对 Agent**：第一次接入，只用 ssh、shell、HTTP 和 MCP，就能取用授权给它的凭据，在一次真实故障中查清问题、在机器上修好，并让人看到它做了什么。
- **对人**：每件事在 Beacon 里做，至少和在原来的工具里一样顺手；其中任何一部分都能授权给 Agent。

## 要解决的问题 {#the-problem}

Agent 干活，需要的和工程师一样：

- **凭据**：它要操作的系统的密码、令牌和密钥；
- **访问**：到机器和服务；
- **眼睛**：监控和告警，既看它运行的，也看它开发的；
- **记录**：做过什么，谁做的，为什么；
- **和人的联系**：被叫醒、汇报、让人看见。

它和工程师有三点不同：

- 它熟悉的是 ssh、shell、HTTP、MCP 这些通用工具，不是各家产品自己的界面；
- 它不记事，每次会话都从零开始；
- 它也不会一直盯着屏幕，得有东西叫醒它。

Agent 自己闭不了环。凭据握在人手里，Agent 能用什么由人决定，同样的活人自己也要做。基础设施要是只有 Agent 能用，人就得另留一套工具，也没法从那套工具里给 Agent 授权。

所以 Beacon 在同一个地方同时服务两边。给 Agent 的每项能力，都按它已有的方式来用；给人的同一项能力，至少要和人今天做这件事所用的工具一样好。

## 为谁 {#who-it-is-for}

- **用 AI Agent 管理自己的机器和服务的人和团队**（Claude Code、Codex 这一类）：从一个人带几个 Agent 管十几台机器，到一个共用密码、分担工作的团队，都是自托管。
- **首先是做 Beacon 的人自己**：自己的活先跑在上面，再给别人用。

## 核心：一切可追溯 {#the-core-everything-traceable}

有了可追溯，人才能放手让 Agent 干活。人不用事前逐步审批，事后能看到每一步，并追到是谁做的、代表谁、为什么。

| 目标 | 怎么算达成 |
| --- | --- |
| **1. 可追溯** | 人和 Agent 的每个动作都有记录：谁做的、代表谁、凭哪次授权、为什么。会话有录像、可以回放；命令、密钥的每次使用、配置的每次修改都有结构化记录，至少保留六个月。记录组成哈希链，并带签名的检查点，缺了一段或被改过都看得出来。一条时间线串起告警、会话、命令、备注和变更，人在控制台和自己的聊天工具里都能看到。命令不用等批准：Beacon 审批的只有凭据，每次授权批一次，从不在每次使用时批 |

## 产品目标：四项能力 {#product-goals-four-capabilities}

每项能力都是人已经有工具在做的一件事。Beacon 按 Agent 的方式给 Agent 做，给人做得至少和那件工具一样好。

| 目标 | 怎么算达成（数字是目标值） |
| --- | --- |
| **2. 密钥**（团队密码管理器）：人和 Agent 保存、共享密码、密钥和令牌 | 一个团队从原来的密码管理器搬过来，什么都不丢：按角色共享的库、常见的条目类型、从常见的密码管理器导入、在浏览器里自动填写、每个条目的历史。Agent 凭授权使用密钥：授权一次，多次使用，授权可以长期有效，也可以续期。它可以用一个值而看不到这个值。每次读取、每次使用都追溯到是哪个人或 Agent、为什么 |
| **3. 可信访问**（身份）：每个 Agent 都有主人，只做被授予的事 | 一个 Agent 在 SSH、REST 和 MCP 上是同一个身份，代表某个人行事，不超出这个人的角色。Claude Code 和 Codex 在浏览器里登录；无界面的 Agent 用一个有作用域、会过期、能自动续期的令牌。Agent 手里的凭据只来自 Beacon。人能看到自己的每个 Agent 和它能做什么，可以吊销其中一个，也可以一次暂停全部 |
| **4. 机器**（SSH 跳板机）：Agent 和人能到达每一台登记过的机器，并在上面干活 | ssh、scp、rsync、`ssh -L` 和 MCP 工具都能到达任何登记过的机器，包括 NAT 后面的。通道带来的额外延迟在 50 ms 以内（实测每次新建连接约 23 ms）。Agent 从不接触密码和密钥。一台机器只登记一次，监控共用这个身份 |
| **5. 监控**（告警和视图）：服务对用户是否正常，哪里坏了，为什么；既管你的机器，也管你的 Agent 开发的服务 | 严重故障 5 分钟内送到 Agent 和人；单个检测点的抖动不打扰任何人；每次失败都带着检测点和原因；一次调用拿全证据。新告警能唤醒 Agent，也能送到人的聊天工具和手机上。Agent 能自己把开发的服务加进监控：检测、指标、告警规则，以及它们的视图。人在控制台里看到同样的视图，用户看到公开状态页 |

## 设计目标 {#design-goals}

| 目标 | 怎么算达成 |
| --- | --- |
| **6. 贴近 Agent 的工作方式** | 用标准协议：SSH、Prometheus 查询、HTTP 加 JSON、MCP；不自创配置语言。MCP 工具和 Agent 自带的工具同名同义：执行命令、读文件、改文件、搜索、后台任务。结果干净、结构化，不夹带终端控制字符；长输出会截断，并说明怎么取到其余部分。错误码稳定，并说明怎么改正 |
| **7. 对人一样好用** | 每项能力都经得起和人今天做这件事所用的工具比：密码管理器、跳板机、可用性监控和监控面板。人在控制台、命令行和聊天工具里管理和授权。一个人能做的，可以授权给 Agent，不能更多 |
| **8. 凭据只在 Beacon 里** | 密码和密钥加密存放在 Beacon 里，只凭授权交给 Agent；连接机器用几分钟就失效的证书；令牌有作用域和有效期；Beacon 自己的密钥只从配置里写明的文件读取 |
| **9. 在 Beacon 里配置** | 目录、检测目标、检测模块和机器都存在 Beacon 的数据库里，通过 API、MCP 和命令行修改，并留下谁改了什么的历史；文件只用于导入和导出 |
| **10. 小** | 中心用一台 2 核 4 GB 的机器绰绰有余；检测程序和机器上的连接程序常驻内存都在 20 MB 以内；30 分钟装好 |
| **11. 开放** | Apache-2.0；实现这些目标所需的一切都在本仓库里；不绑定任何模型、聊天工具或云厂商 |
| **12. 能托管而不必分叉** | 只预留接缝（工作区、存储接口、协议版本、计量），让托管部署始终可行；这些都不提前实现 |

## 不做什么 {#not-doing}

- **Beacon 不是 Agent，也不调用任何模型**。它唤醒 Agent；Agent 被唤醒时，`beacon-oncall` 启动你指定的 Agent 程序。推理和审核是 Agent 的事，Beacon 是它们干活的地方。
- **不审批 Agent 执行什么**。执行什么由 Agent 决定，由运行它的那一层自己审核。审批只针对凭据，每次授权批一次，从不在每次使用时批。机器上的刹车是暂停开关和每台机器的访问范围。
- **不做日志平台、链路追踪和 APM**。Agent 要看日志，就通过 SSH 通道直接读（journalctl 之类），这是它最熟悉的方式。视图展示的是 Beacon 本来就存着的指标和检测结果。
- **不自己做时序数据库**。存储和查询交给 VictoriaMetrics。
- **不做远程桌面，也不做部署系统**。Flux 这类工具照常用，Beacon 接收它们的变更事件。
- **不写只有某一处部署才需要的代码**。某处部署特有的东西都是配置，放在本仓库之外。

## 什么叫落地 {#what-landed-means}

以下三条同时成立，项目就算落地（1.0）：

1. **在 Beacon 运行的地方**，人和 Agent 四件事都用 Beacon 来做。团队的密码都在里面，原来的密码管理器已经退役。Agent 用到的每份凭据都经它授权，每台机器都经它到达；每条严重告警都会唤醒 Agent，多数由 Agent 处理完。
2. **另一个团队**照着 README 用参考部署，30 分钟装好 Beacon。它导入自己的密码，登记一个检测点、一台机器和自己已经在用的 Agent 程序（Claude Code、Codex 或别的），同样的东西就在它自己的聊天工具里跑起来。
3. **人有一个地方可看**。从聊天里的卡片点一个链接，就能打开告警的时间线、每次会话的回放和暂停开关。每次授权、每次使用密钥，都能在控制台里追溯。人用 Beacon 自带的账号登录，不接外部登录。

## 目标冲突时 {#when-goals-pull-apart}

首先是可追溯：没有一步不留记录。其次是不泄露凭据、不丢告警。再次是贴近 Agent 的工作方式，以及人用起来不输熟悉的工具。然后是保持小巧。最后才是更多功能。
