# 运维控制台

用控制台接手告警、通过 SSH 连接机器，并向下一班交接故障。总览会显示需要处理的事项。控制台还可以：

- 查看告警、处置人和复测结果；
- 安排维护并查看静默；
- 查找成员和 Agent 发起的会话录像；
- 管理成员、Agent 和访问权限，或暂停 Agent 访问机器；
- 添加常规 HTTP 监控并查看配置历史。

Agent 通过 [REST API](../reference/api.md) 和 [MCP 工具](../reference/mcp.md) 使用同一套故障记录。有效的卡片签名链接可打开事件供查看。登录后可访问你的角色允许的页面和操作。

如需让同事用自己的账号操作，可以[邀请团队成员](people.md)。

控制台由 Beacon 自己提供，在 `public_url` 下的 17001 端口、与 API 和 MCP 并排的 `/console` 上。站点根路径 `/` 是公开的（[发布状态页](status-pages.md)）。

发布版本中的 `/console` 默认进入 `/workspace/` 上的 React 控制台。概览、告警、成员、Agent、**MCP 与 API** 能力中心（`/workspace/capabilities`）、机器、监控、配置和回放使用同一套导航、浅色/深色/跟随系统主题切换、`⌘K` 快速跳转与账号权限。静态前端与会话 API 由同一个容器提供。若站点根路径 `/` 未挂载默认公开状态页，则会呈现介绍 Beacon 多地共识探测、SSH 通道、MCP 服务及已发布状态页的产品首页。

## 登录 {#signing-in}

打开 `https://status.example.com/console`。按提示输入用户名和密码，Beacon 随后打开你请求的页面。

- **一次登录保持 12 小时。**
- **浏览器只保存会话 id**，放在 `HttpOnly`、`Secure`、`SameSite=Strict` 的 cookie 里。Beacon 那边只存它的 SHA-256。
- **cookie 是 `Secure` 的**，所以控制台要走 HTTPS（或 `localhost`）。
- **会话能做什么由成员的角色决定**，每个请求都重读。调低角色立刻生效。
- **停用账号或改密码**会结束其会话。

登录失败时，表单会说明原因。[登录控制台失败](../self-hosting/troubleshooting.md#signing-in-to-the-console-fails)列出了每条消息和对应的处理。

表单下方的**用令牌登录**仍然接受粘贴进来的 Beacon 令牌，再保留一个版本。它给脚本用，也给还没有账号的 Beacon 用，那里只有这一种方式。

- 令牌至少要有 `status:read`。
- 会话持续 12 小时并绑定该令牌，吊销令牌即结束会话。
- 用令牌登录的会话不能允许 MCP 客户端：OAuth 客户端总是以某个人的名义行事。

## 各个页面 {#the-pages}

每个页面同一个框架：

- 按任务组织的侧栏，手机上通过菜单按钮打开；
- 面包屑下方是页面标题和主要操作，**告警**列表可按需打开筛选侧栏；
- 页面底部 Beacon 的版本，以及指向文档、源码、问题反馈的链接。

列表最新的在前，每页 50 条。每个筛选都是链接，所以每个视图都有可以分享的 URL。

先在**概览**查看需要处理的事项。其他入口按任务组织：

- **故障处置**打开当前告警、每轮故障的历史、Agent 投递与执行，以及 CI 和 Flux 上报的变更。
- **监控**打开服务检测、静默与维护、公开状态页。**监控项**页面可以直接跳转到服务、心跳和资源。
- **SSH 访问**打开机器登记与连接指引，以及当前身份可查看的会话和录像。
- **成员与 Agent**打开成员与角色、你管理的 Agent 和委托权限，以及展示六大运维域、实时 MCP 工具/资源/提示词与可复制 Claude Code / Codex 接入命令的 **MCP 与 API** 能力中心。
- **管理**打开配置及其历史、访问令牌、审计日志和已启用的团队凭据。

| 页面 | 显示什么 |
| --- | --- |
| `/console` 概览 | 有没有需要处理的事、五个数字，以及 Beacon 发现的问题（[见下](#the-overview)） |
| `/console/alerts`、`/console/alerts/{id}` | 所有告警组（已恢复的留 7 天），可按状态、严重程度、服务、已确认、已静默筛选。告警页（[见下](#the-alerts-page)）带确认、静默、结束静默、加备注的表单 |
| `/console/monitors`、`/console/monitors/{service}` | 监控了什么、现在怎么样（[见下](#monitors-and-status-pages)） |
| `/console/status-pages`、`/console/status-pages/{name}` | 公众现在看到的状态页（[见下](#monitors-and-status-pages)） |
| `/console/silences` | 让告警不去通知人的东西：维护窗口和静默（[见下](#silences-and-maintenance)） |
| `/console/machines`、`/console/machines/{name}` | 通道能到达的机器、NAT 后的机器是否连着、最近 24 小时的会话。有 `machines:write` 时：添加机器，修改备注、是否关键和账户，重新固定主机密钥，更换连接器密钥，以及输入机器名之后移除它。单台机器的地址、主机密钥、最近会话和上面执行过的命令。可按机器名称、地址或备注搜索。需要登记时打开**添加机器**。有 SSH 权限的成员可选择 **SSH** 获取以本人身份连接的命令和终端配置。独立的**暂停全部 SSH 访问**按钮会停止通过 Beacon 的机器操作，监控继续运行 |
| `/console/sessions`、`/console/sessions/{id}` | 当前登录身份可访问的会话，可按 Agent、机器、类型、连接方式、退出状态和日期筛选。有会话详情权限时可搜命令，打开会话页可播放录像（[见下](#the-sessions-page-and-its-replay)） |
| `/console/agents`、`/console/agents/{name}` | 你的 Agent（所有者看到所有人的）：各自现在能做什么、凭据、密钥。可展开 OAuth 客户端的接入说明和无界面 Agent 的令牌表单。编辑时会显示所选预设的权限，可明确选择授予全部现有及将来登记的机器，或仅指定机器。每个 Agent 的页面可改预设和机器，并可吊销其凭据。以本人身份登录的所有者还可以在那里设置自定义 scope |
| `/console/tokens` | 所有令牌：scope、机器、密钥、到期、属于谁的 Agent。账号出现之前的标成**Legacy**，旁边是认领表单。永远不会出现密钥本身 |
| `/console/config`、`/console/config/history/{version}` | 配置只读（检测点、心跳、资源、目标集、模块）及其历史。谁、何时、经什么、为什么；每个版本逐项显示为 diff，可回退 |
| `/console/hooks` | 已配置的 Agent 钩子和每一次调用：钩子、事件、状态、尝试次数、时间、为哪条告警 |
| `/console/people`、`/console/account` | 成员和角色：邀请、改角色、停用、密码重置（[邀请你的团队](people.md)）。你自己的账号和密码 |
| `/console/changes`、`/console/audit` | 来自 CI 和 Flux 的变更事件。审计日志，可按谁、动作、via 筛选 |
| `/console/setup`、`/console/join`、`/console/reset`、`/oauth/authorize` | 一次性链接打开的页面，和 MCP 客户端引导成员前往的授权页 |

### 概览 {#the-overview}

`/console` 首先显示当前健康状态。如果严重告警没有通知人员的渠道，这里会提示。状态区能打开触发中的告警、正在监控的服务和检测点。覆盖条按最近五分钟内实际在上报的检测点计数。

各尺寸的屏幕都在状态区下方显示待处理队列。展开**系统详情**可查看机器连接情况、今天的 SSH 会话、通道状态和配置版本。

**需要处理**先列触发中的告警，最严重的在前。已认领或静默的告警排在其余之后。Pushover 设备回应可以暂停新的升级通知。触发中且未静默的告警会留在**告警 → 等待人员接手**，直到有人接手。随后，**需要处理**会列出 Beacon 发现、但还没有触发中告警提到的问题：

- 服务失败；
- 检测点不再上报；
- NAT 后的机器没连上；
- Hook 没能唤醒 Agent；
- 通道被暂停。

概览还会显示：

- 公众现在看到的状态页；
- 近期安排：进行中或计划中的维护，以及 30 天内到期的资源；
- 今天唤醒的 Agent；
- 最近的会话和变更。

**严重告警通知**会显示各渠道的发送时机和最近的提供方响应。Beacon 能将 Pushover 的设备回应关联到当前目的地已受理的通知时，会显示这条回应。选择**验证聊天通知**或**验证手机通知**，可以在新标签页打开相应演练指南，核对预期接收方是否实际收到了通知。

### 监控和状态页 {#monitors-and-status-pages}

`/console/monitors` 显示监控了什么、现在怎么样：

- **每个服务**：目标集检测的每个服务，有问题的在前，带它在各检测点的状态、检测目标、显示它的状态页和正在触发的告警；
- **每个心跳**，带最近一次成功的时间；
- **每项资源**，带到期时间。

单个服务的页面有各检测点最近 30 分钟对它的目标的检测结果和原因。还有它的目标及所属目标集，以及它的告警。

有 `config:write` 时，点击**添加 HTTP 监控**，选择检测地址、方案和位置。保存后立即打开服务页，可以查看首次检测结果。改动会进入**配置**历史。参见[检测一个服务](monitoring.md#add-an-http-monitor)。

对于导入的 HTTP 监控，具有 `config:write` 和 `machines:write` 的已登录人员可以在**检测目标**中为符合条件的组选择**更改指定机器**。保存前请核对目标集、检测位置、故障域、页面标签、可见性和端点。可选择一台已登记的机器，也可通过**不指定机器**清除选择。此操作只修改应急处置使用的机器。目标集仍由原配置来源管理，再次导入前请在那里保留指定信息。若一个告警涵盖多个分组，所有这些分组指定同一项机器登记时才会关联机器。重新指定机器会影响新故障。仍在告警的故障若后来加入了冲突的告警条目，已有的机器关联可能会撤下。

`/console/status-pages` 显示公众现在看到的状态页：每个页面的地址、状态、组件、进行中的事件和维护窗口。单个页面的视图有：

- 各组件，及背后的服务、它们的状态和 90 天可用率；
- 它的事件，各自链接到对应告警；
- 它的维护；
- 页面本身、JSON、订阅和徽章的链接，即 Beacon 在 `/status/<name>` 下提供的那份。

### 机器设置历史 {#machine-settings-history}

在机器页面打开**设置历史**，可查看每个版本的账户、关键机器标记、备注和修改人。拥有 `machines:write` 权限的人员可以把早期设置复制到新版本。如果当前版本已变动，控制台会拒绝此次编辑或恢复。刷新页面即可查看最新变更。

新增登记或明确替换机器会开启新的设置历史。恢复设置时保留当前地址和密钥。对于功能上线前已有的机器，第一次编辑时会保存修改前的设置。

### 静默和维护 {#silences-and-maintenance}

`/console/silences` 显示让告警不去通知人的东西：

- **维护窗口。** 进行中和计划中的在前，然后是最近结束的 20 个。各带服务、时间和计划人。
- **静默**：生效中或即将生效的，即 Alertmanager 里的那些。各自显示匹配什么、备注、谁建的、何时结束、静默的是哪条告警。Agent 的静默会单独标出：它只被记录，仍会通知人。

谁能结束什么：

- 有 `maintenance:write` 的人可以安排维护、提前结束窗口，或在开始前取消。
- 能静默的人（`alerts:write`）可以结束静默。
- 维护窗口的静默随窗口一起结束。

点击**安排维护**，选择服务并预览会公告维护的公开页面和组件。在服务的监控详情里打开表单，会预先选中该服务。Agent 和脚本可以用 `schedule_maintenance` 或 `POST /api/v1/maintenance`。

### 表单和角色 {#forms-and-roles}

控制台的表单就是 API 和命令行的操作，scope 相同。它们以登录成员的身份执行，`via` 记作 `console`。和每一次写入一样，都记入审计日志并回显到告警群。

角色不允许的表单不会出现，强行提交也会被拒绝。角色不允许的页面显示「Not with your role」，并说明需要哪个 scope、你是什么角色。

### 团队凭据 {#team-credentials}

启用凭据库后，所有者可以保存或替换访问令牌，以本人身份发送测试请求，也能将同样的请求授权给 Agent 或撤销授权。参见[使用团队凭据](team-credentials.md)。

## 告警页 {#the-alerts-page}

卡片上的**时间线**按钮可打开告警页。桌面版把处置区放在证据旁边，手机版把处置区放在证据上方。处置区显示告警已触发多久、谁已认领，以及钩子和通知渠道的提交结果。**最新备注**会显示最近更新及其作者和时间。**认领备注**显示当前认领时写下的内容。打开**全部备注**可读到完整内容和较早的更新。Agent 钩子失败时会有独立的状态提示。你可以在这一区域认领、接手、立即复测或跳到备注表单。

新的通知会打开它描述的那次故障，即使同一服务已经再次告警。完整证据被替换或超过保留期限后，登录即可打开该次故障的历史记录。旧版发出的链接仍打开告警组。操作表单打开期间如果告警进入新一轮，请核对告警后再操作。

告警证据中的会话结束后，飞书应用会更新原有卡片。**已结束的 SSH 会话**列出会话数、机器数、命令数和最近一次会话的结束时间。从**时间线**可以打开回放。Beacon 会合并同一卡片上的会话更新，每次至少间隔五分钟，并把飞书额度的最后 10% 留给紧急通知。

登录后，处置区的**关联机器**会链接到规则的 `machine` 标签或心跳目录明确指定的已登记机器。有 SSH 权限的成员会看到如何以自己的身份连接。其他成员可查看机器详情。回到告警页，从**会话**打开记录，再到**备注**记录交班信息。

首次从事件连接机器时，选择**添加 SSH 密钥**，保存公钥后选择返回该机器的 **SSH 设置**。选择**返回事件**即可回到同一次故障，继续复测与交班。

**指定的服务机器**显示服务故障开始时常规 [HTTP 监控](monitoring.md#add-an-http-monitor) 选定的机器。打开机器详情，即可连接并查看账号有权访问的会话。

- **告警本身**：标题、状态、严重程度、起始时间、标签、runbook。
- **通知与处置**区显示渠道接收、提交失败、认领记录和静默。渠道接收表示提供方的 API 已接收发往配置目的地的请求。Pushover 会报告设备是否回应了紧急通知。处置区会显示设备回应何时暂停了新的升级通知，人员接手后仍保留此前的设备回应。控制台认领后，Beacon 暂停发起新的升级通知。此前发出的 Pushover 紧急通知在等待取消时仍可能重复响铃。处置区会显示正在取消、Pushover 已确认取消或重试时限已结束。选择 **刷新状态** 可以查看 Pushover 是否已确认取消，或重试时限是否已结束。对于无法确认取消的通知，或没有取消结果记录的旧通知，处置区也会给出提示。时间线分别展示提交和取消尝试。可以用按钮结束静默。
- **Probes**：告警服务在每个检测点的最新结果和原因，与 `get_evidence` 给的一致。
- 同一故障域里的**相关告警**。
- **Agent**：能否使用机器、各钩子的通知投递状态，以及一行「N sessions on M machines, K commands」。
- **会话**：告警时间窗内相关机器的会话，按当前机器访问权限筛选。有会话详情权限时可点**回放**进入会话。
- **Notes**、**Changes**和**Timeline**：以上一切按时间排好，与 `get_timeline` 给的一致。

时间窗从告警开始前 30 分钟起，与[证据](on-call.md#the-evidence)相同。**立即复测**最多等待 45 秒，随即打开时间线上的结果，按检测点和目标显示失败或缺失的结果。

重新打开告警或接手时，处置区的**最近一次复测**会显示最新已记录的结果及完成时间。选择**查看复测结果**即可打开各检测点的观测。时间线仍保留较早的复测。新的复测进行期间，处置区继续显示最近一次已记录的结果。告警状态仍由监控规则判定。

## 故障历史 {#incident-history}

打开**按开始时间查看故障**，可查看选定 UTC 时段内开始的故障，其中包括仍在告警的故障。按严重级别和来源筛选，再打开单次故障查看证据。列表同时展示钩子接收、程序回报、通过复测和已记录的参与情况。手机设备回应可在该故障的通知记录中查看。较早的故障若没有记录初始级别，使用最近记录的级别。页面会显示已恢复故障的最早保留时间。

从**告警**打开**故障历史**，可回看每次已恢复的故障。同一个告警组重新触发时，每次故障都有独立的记录。历史记录包含告警转为已恢复的时间、每类已确认身份最近的一项告警操作，以及最近一次复测的通过、失败和缺失数量。独立凭据显示为身份未确认。钩子送达本身不算 Agent 已参与处理。

使用**严重级别**、**恢复时间**和**证据**筛选保留的故障。交班复盘时，可选择**严重**和**未记录通过的复测**，找出在告警规则判定恢复前后没有保留完整通过复测的故障。每一行都会显示已有的证据，并单独列出最近的复测结果。即使最近一次复测有失败或缺测，之前完整通过的复测仍可能保留。

Agent 触发运行报告来自告警触发后的程序执行流程，也包括程序无法启动的报告。人工认领来自已确认身份的人员。较早的记录可能缺少这些证据。打开单次故障，可以查看已记录的认领人员、Agent 报告和复测结果。

选择**Agent 发起的复测已通过**，可查找由身份已确认的 Agent 发起并保留的完整通过复测。打开故障，可一起查看复测时间、发起方和相关操作。

**Agent 投递与执行**保留该次故障的钩子投递状态及程序回报。可以查看钩子何时受理，以及程序是否报告启动、失败或完成。程序回报记录的是执行器观测到的结果。较早已归档的故障可能缺少这部分证据。

Beacon 还会保留告警规则判定恢复前后的一次完整通过复测。优先保留规则判定恢复前或同时完成的最后一次完整通过复测。如果此前没有完整通过，则保留规则恢复后首个完整通过的复测。完整通过要求至少有一个待测的目标与位置组合，而且每个待测组合均成功。复测时间是 Beacon 完成结果收集的时间。可以将这次通过与后续有失败或缺测的复测对照，也可在记录留有身份时查看各次复测的发起人。

**相关审计记录**会打开按告警组和该次故障时间范围筛选的审计日志。签名检查点用于校验审计日志。故障历史是可观察活动的摘要，不能证明是哪一方促成了恢复。

完整告警证据在恢复后保留七天，告警组再次触发时会更新为新一轮详情。之后故障摘要保留最多八个关联会话的链接。故障摘要在恢复后按 `storage.incident_retention` 保留，默认 180 天。审计记录和会话录像按各自的设置保留。只有具有 `status:read` 的访问者能看故障历史，公开状态页另行生成。升级前已清理的故障无法还原。

## 会话页与回放 {#the-sessions-page-and-its-replay}

会话页显示：

- 谁、在哪台机器上、经什么（ssh、MCP 还是 API）；
- 何时开始、用了多久；
- 退出状态；
- 录像和命令文字记录各自的采集状态。

可用的 asciicast v3 录像可下载，或通过 [asciinema-player](https://github.com/asciinema/asciinema-player) 回放。它可以包含输入、输出、窗口尺寸变化、shell 命令标记和退出状态。**命令文字记录**区显示已采集的结构化 shell 命令及退出状态，或单条命令的输出。

**待完成采集**表示 Beacon 尚未记录会话结束。**已截断**表示只采集了部分内容，已保存的部分可在文件可用时打开。页面会分别显示存储读取失败和旧记录采集状态未知。SFTP 和端口转发会保留连接信息。未提供可用命令集成的 shell 可能有可回放的录像，但**命令文字记录**区仅有会话信息。

控制台会按你当前的权限显示会话列表、告警时间线、命令文本和录像。只允许访问指定机器的凭据，只能看到属于这些机器当前登记记录的会话。以相同名称重新登记机器会生成新的登记记录。带 `status:read` 的凭据可以查看权限范围内的会话摘要。查看命令文本或录像需要 `sessions:read` 或 `machines:ssh`，也需要有权限访问该会话对应的机器。较早的 SSH 审计记录仅以机器名称标识时，命令文本只向可以读取所有机器会话详情的凭据显示。

## 签名链接 {#signed-links}

拿到 Beacon 签名链接的人无需登录即可打开分享的页面。签名包含在 `s` 查询参数中，签名密钥由 Beacon 保存在数据库中。链接有效期由 `pages.link_ttl` 决定，默认 30 天。未登录访问已过期、已撤销或签名无效的链接时，Beacon 返回普通的 404。

告警链接可查看单次告警事件。要响应告警、打开相关告警或查看 SSH 回放，请用自己的账号登录，并按账号权限访问。相关 SSH 会话的命令文本遵循与回放相同的访问权限。未登录的访客可用会话链接打开该会话，并在录像可用时播放或下载。点击**登录**会回到同一个页面。已登录时打开分享地址，会使用你当前的角色和机器访问权限。

在控制台分享时，请用所有者账号登录，打开告警或会话，选择**管理分享链接**，再点**创建分享链接**。复制显示的链接并核对过期时间。告警分享链接指向当前事件，事件详情保留期间可打开。请只将链接发送给适合查看该告警或录像的人，并按对方需要的访问时长设置 `link_ttl`。

在管理页面选择**撤销所有分享链接**，可停用先前为该资源签发的链接。

- 告警的撤销范围涵盖同一告警组内的所有事件，包括聊天中的链接。
- 会话的撤销范围涵盖会话页及其录像签名链接。

撤销后可以再创建新链接。先前为相关告警或会话签发的链接各自独立，需要到对应资源的管理页面撤销。已登录用户仍可按账号权限访问。

Beacon 在数据库中保存撤销记录。恢复较早的备份也会恢复当时的撤销状态，因此在备份之后撤销的链接可能重新生效，直到过期。

卡片的 **Timeline** 按钮和 REST、MCP 应答中的告警链接使用该次故障的签名地址。告警群中的 **Replay** 链接和 REST、MCP 应答中的会话链接会引导读者登录后查看该会话。已签发的签名链接沿用原有的过期和撤销规则。

较早的链接可能指向站点根下的 `/alerts/{id}` 或 `/sessions/{id}`。有效链接会重定向（`308`）到 `/console` 下对应的页面。过期和撤销规则同时适用于新旧路径。控制台其余旧路径也会带着查询参数重定向，书签仍可使用（[控制台在旧链接上显示 404](../self-hosting/troubleshooting.md#the-console-says-404-on-an-old-link)）。

## 也可以用令牌 {#tokens-instead}

任何带相应 scope 的凭据，都能像打开对应 API 路由一样打开告警页和会话页，只读。凭据可以是令牌（`lbt_…`）或 OAuth 访问令牌（`lba_…`），需要：

- 告警页：`status:read`；
- 会话页及其录像：`sessions:read` 或 `machines:ssh`。

以 `Authorization: Bearer …` 发送。缺 scope 的、未知的和什么都不带的，得到的是同一个 404。

## 它怎么做的，它不做什么 {#how-it-is-built-what-it-does-not-do}

控制台基于 OpenLinkOS 设计系统（[`@openlinkos/ui`](https://github.com/openlinkos/design/tree/master/packages/ui)），用它的工位框架和 Beacon 的品牌，家族的工具长得一样。

- **不从别处取任何东西。** 样式表、字体和播放器的代码都嵌在 Beacon 的二进制里。`Content-Security-Policy` 只允许来自 Beacon 的脚本、样式、字体和表单。
- **一套页面适配所有屏幕**，全靠 CSS：1200px 起完整侧栏，860px 起图标栏，手机宽度下列表重排成卡片。
- **外来文字经过清理。** 来自 Beacon 之外的文字（告警注解、备注、命令）经 bridge 清理，输出时转义。
- **语言和配色。** 控制台跟随配置的语言（中文或英文），以及系统的深浅色。
- **不被索引。** 页面带 `noindex`，因为页面链接里带着签名。

它不做的两件事：

- **不从任何别处登录。** Beacon 自己的账号是唯一的入口。
- **没有审批流。** 表单就是成员角色经 API 本来就允许的操作，刹车是暂停开关。

高级检测、目录和状态页定义通过文件、API、MCP 的 `put_config` 或命令行配置。所有入口的配置改动都会经过检查、保留版本并记录改动者。

## 检查一下 {#check-it}

以人的身份走一遍循环：

1. **打开一条告警**，从卡片或 `/console/alerts` 进去。
2. **读它的检测点和时间线。** 你会看到每个检测点的最新结果及其原因，以及按时间排好的各事件。
3. **打开权限范围内的一次会话回放。** 在**会话**中选择**回放**。
4. **确认记录完整。** 把 `get_timeline`（或 API 的 `GET /api/v1/alerts/{id}/timeline`）与告警页对照。两边应是同样的事件：钩子的调用、会话、`probe_now` 的结果和备注。
